# Доклад: Сравнительный анализ LLM-моделей, эмбеддингов, векторных БД и выбор конфигурации для RAG-бота

## 1. Сравнительный анализ LLM-моделей

### 1.1 Качество ответов

| Модель | Оценка качества |
|--------|----------------|
| **Hugging Face (локальные)** | Экосистема предоставляет широкий спектр моделей (например, YandexGPT-5-Lite-8B). Минимальная RAG-система повышает точность до 33% на MMLU Pro. Локальные модели можно дообучить под специфику компании. |
| **OpenAI (облачные)** | GPT-4o показывает высокие результаты (MMLU 77.3). С февраля 2026 года модели GPT-4o и GPT-4.1 выведены из ChatGPT, но API-доступ сохранён для бизнеса. |
| **YandexGPT (облачные)** | YandexGPT 5 Pro превосходит предыдущую версию в 58% тестов и обходит GPT-4.1 в 56% тестов, особенно в русскоязычных задачах. В RAG-сценариях даёт до 70% лучшей обработки внешних источников. |

### 1.2 Скорость работы

| Модель | Особенности скорости |
|--------|----------------------|
| **Hugging Face** | Зависит от GPU (A100 и vLLM дают низкую задержку). |
| **OpenAI** | Задержка из-за сети; лимиты: 500 запросов/мин, 30 000 токенов/мин (Tier 1). |
| **YandexGPT** | Стабильная задержка в РФ; YandexGPT 4 показал двукратное увеличение скорости и снижение ошибок до 2,1%. |

### 1.3 Стоимость владения и использования

| Критерий | Hugging Face | OpenAI | YandexGPT |
|----------|--------------|--------|------------|
| Модель затрат | Инфраструктурная | Оплата за токены | Оплата за токены |
| Цена за 1M токенов (вход) | Зависит от GPU ($500–2000+/мес) | GPT-4o: $2.50–$5.00 | Lite: ~$2.30 |
| Цена за 1M токенов (выход) | Зависит от GPU | GPT-4o: $10.00–$15.00 | Lite: ~$2.30 |
| Порог окупаемости | 14 000–35 000 запросов/мес | — | — |

*При объёме 1 млн запросов/мес: YandexGPT Lite ≈300 000 ₽, YandexGPT Pro 5.1 ≈1 200 000 ₽, DeepSeek V3.2 ≈900 000 ₽.*

### 1.4 Удобство и простота развёртывания

- **Hugging Face:** Требует экспертизы для инфраструктуры, управления моделями, отказоустойчивости, масштабирования.
- **OpenAI:** Максимально прост – API-ключ и несколько строк кода. Идеален для прототипирования.
- **YandexGPT:** Аналогично OpenAI, данные в РФ (152-ФЗ), обучен на русском, не требуется VPN. Используют >25 000 компаний.

## 2. Сравнительный анализ моделей эмбеддингов

### 2.1 Скорость создания индекса

| Характеристика | Sentence-Transformers (локальные) | OpenAI Embeddings (облачные) |
|----------------|------------------------------------|------------------------------|
| Модель | all-MiniLM-L6-v2 (384 dim) | text-embedding-3-large (3072 dim) |
| Скорость | ~1.72 с (2x быстрее OpenAI) | ~3.56 с |

### 2.2 Качество поиска

- **Sentence-Transformers:** На 11,4% выше производительность по сравнению с OpenAI при нулевых затратах. Модель Stella показывает «превосходную производительность сразу после установки».
- **OpenAI Embeddings:** Высокая точность и лёгкость внедрения, идеальны для прототипов.

> *Качество поиска сильнее зависит от семантического разрыва, чем от выбора модели эмбеддинга.*

### 2.3 Стоимость владения

| Параметр | Sentence-Transformers | OpenAI Embeddings |
|----------|----------------------|-------------------|
| Стоимость | Нулевая после покупки оборудования | $0,13 за 1K токенов (large), $0,02 (small) |
| За 1 млн слов | — | $26 – $169 |
| Доп. расходы | Нет | OpenAI Assistants: $0,10/ГБ в день |

## 3. Сравнительный анализ векторных баз данных (ChromaDB vs FAISS)

### 3.1 Скорость поиска и индексации

| Характеристика | ChromaDB | FAISS |
|----------------|----------|-------|
| Время запроса (35K записей, CPU) | ~7 мс | ~23,7 мс |
| p99 задержка (100M векторов, 100k QPS) | 8,0 мс | 2,1 мс |
| Recall@10 (100k QPS) | 96,2% | 98,7% |
| Максимальный размер датасета | 120M векторов | 1B+ векторов |

**Выводы:**
- FAISS **в 4,2 раза быстрее** ChromaDB на больших масштабах.
- ChromaDB быстрее на небольших датасетах и CPU (7 мс против 23,7 мс).

### 3.2 Сложность внедрения и поддержки

| Критерий | ChromaDB | FAISS |
|----------|----------|-------|
| Установка | `pip install chromadb` | `pip install faiss-cpu` |
| Полноценная БД? | Да | Нет (библиотека поиска) |
| Управление метаданными | Встроенное | Отсутствует |
| Фильтрация | Да | Нет |
| Персистентность | Встроенная (Parquet) | Требуется ручная |

### 3.3 Стоимость владения

| Критерий | ChromaDB | FAISS |
|----------|----------|-------|
| Лицензия | Apache 2.0 | MIT |
| Операционные затраты | Низкие | Высокие (из-за «допиливания») |
| ROI | Лучше для средних проектов | Лучше для высоконагруженных систем |

FAISS дешевле в чистой вычислительной стоимости на больших масштабах, но требует реализации метаданных, персистентности, мониторинга и DevOps-ресурсов.

## 4. Рекомендуемая конфигурация сервера для RAG-бота

| Компонент | Минимальная конфигурация | Рекомендуемая конфигурация |
|-----------|--------------------------|----------------------------|
| CPU | 4 ядра / 8 потоков | 16–32 ядра |
| RAM | 32 ГБ DDR4 | 64–128 ГБ DDR5 |
| GPU | RTX 3060 12 ГБ | RTX 4090 24 ГБ / A100 80 ГБ |
| Storage | 512 ГБ NVMe SSD | 2 ТБ RAID0 NVMe |

**Обоснование:**
- **GPU** – критичен для инференса LLM и эмбеддингов. Рекомендуется 24+ ГБ для моделей 70B+ в квантованном виде.
- **RAM** – для хранения векторных индексов и кэширования.
- **CPU** – для предобработки данных и вызовов API.

## Итоговые рекомендации для компании (4 варианта)

### Вариант 1. Облачный API (MVP / прототип)
- **LLM:** OpenAI GPT-4o / YandexGPT 5 Pro (API)
- **Эмбеддинги:** OpenAI text-embedding-3-large
- **Векторная БД:** ChromaDB (embedded)
- **Сервер:** не требуется  
*Плюсы:* быстрый старт, нет CAPEX. *Минусы:* высокие OPEX (>$0,05/запрос), зависимость от API.

### Вариант 2. Полностью локальный стек
- **LLM:** Hugging Face (Llama 3–70B / DeepSeek-R1)
- **Эмбеддинги:** Sentence-Transformers
- **Векторная БД:** FAISS (скорость) или ChromaDB (простота)
- **Сервер:** A100 80 ГБ + 128 ГБ RAM  
*Плюсы:* контроль данных, нет per-query затрат. *Минусы:* высокий CAPEX ($20k+), нужен MLOps.

### Вариант 3. Гибридный (рекомендуемый)
- **LLM:** YandexGPT 5 Pro (API)
- **Эмбеддинги:** Sentence-Transformers (локально)
- **Векторная БД:** ChromaDB (локально)
- **Сервер:** RTX 4090 24 ГБ + 64 ГБ RAM  
*Плюсы:* баланс стоимости и контроля, соответствие 152-ФЗ, экономия на токенах эмбеддингов.

### Вариант 4. Корпоративный кластер
- **LLM:** Fine-tuned Hugging Face
- **Эмбеддинги:** Sentence-Transformers (fine-tuned)
- **Векторная БД:** FAISS + PostgreSQL для метаданных
- **Сервер:** кластер из 2+ серверов A100 80 ГБ  
Для >50 000 запросов/мес окупается локальное решение. При 100 000 запросов/мес экономия 53–86%.

## Вывод: выбор векторной БД

**Рекомендуется ChromaDB** для создания RAG-бота компании по следующим причинам:

1. **Простота внедрения** – `pip install chromadb`, работает из коробки с метаданными и персистентностью.
2. **Достаточная производительность** – на 35K документов ~7 мс (быстрее FAISS на CPU).
3. **Совместимость с LangChain** – ускоряет разработку.
4. **Лицензия Apache 2.0** – безопасна для коммерции.
5. **Масштабируемость** – стабильна до 120 млн векторов.
6. **Поддержка DuckDB-backed HNSW** – эффективна даже при 100M+ векторов.

**FAISS выбирать только если:**
- Требуется экстремальная скорость (миллионы QPS);
- Датасет >100 млн векторов при жёстком бюджете;
- Есть команда для реализации метаданных, мониторинга и персистентности.

> **Итог:** ChromaDB обеспечивает оптимальный баланс производительности, удобства и стоимости владения для большинства корпоративных RAG-проектов.
